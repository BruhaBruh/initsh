# initsh

Первичная настройка свежего VPS на Debian/Ubuntu одной командой с локальной машины.

Что делает:

- создаёт пользователя (по умолчанию `bruhabruh`) с sudo **по паролю**;
- кладёт твой публичный ключ (`~/.ssh/id_rsa.pub`) в `authorized_keys`;
- запрещает вход под root и по паролю (`PermitRootLogin no`, `PasswordAuthentication no`, `AllowUsers`);
- ставит fail2ban для sshd; IP, с которого ты запускаешь скрипт, попадает в `ignoreip`;
- включает ufw и открывает только 22, 80 и 443;
- включает unattended-upgrades (автоматические обновления безопасности).

Работа идёт в две фазы, чтобы не отрезать себе доступ. В первой фазе под root создаётся пользователь и ставятся пакеты. Затем скрипт **проверяет, что новый пользователь входит по ключу**. Root и пароли закрываются только после этого, а в конце ещё раз проверяется, что вход работает, а root не пускают.

## Требования

- **Локально:** `bash`, `ssh`, `openssl`, ключ `~/.ssh/id_rsa.pub` (и приватный `~/.ssh/id_rsa`).
- **Сервер:** Debian/Ubuntu (проверено на Debian 12 и Ubuntu 24.04), вход под `root` по ключу или паролю.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/BruhaBruh/initsh/main/init.sh | bash -s -- <ip>
```

Работает в bash, zsh и fish.

Нестандартный SSH-порт передаётся вторым аргументом: `... | bash -s -- <ip> 2222`.

Можно и без curl, из клона репозитория: `./init.sh <ip>`.

> Перед запуском скрипта из интернета прочитай его: он ходит на сервер под root.

## Настройки

| Переменная    | По умолчанию          | Что это                        |
|---------------|-----------------------|--------------------------------|
| `INIT_USER`   | `bruhabruh`           | имя создаваемого пользователя  |
| `PUBKEY_FILE` | `~/.ssh/id_rsa.pub`   | какой публичный ключ положить  |

```sh
curl -fsSL https://raw.githubusercontent.com/BruhaBruh/initsh/main/init.sh \
  | INIT_USER=deploy PUBKEY_FILE=~/.ssh/id_ed25519.pub bash -s -- 203.0.113.10
```

Список открытых портов задаётся массивом `UFW_ALLOW` в начале `init.sh`.

Если нажать Enter, пароль сгенерируется и выведется в конце. **Сохрани его**, он нужен для `sudo`:

```text
[init 2026-11-01 09:04:28] Готово: ssh -p 22 bruhabruh@203.0.113.10
Пароль bruhabruh (для sudo), сохрани:  xK3pQ9vLm2TfR8sWn4YcHb7J
```

Если новый пользователь не смог войти по ключу, скрипт остановится **до** закрытия root:

```text
ОШИБКА: bruhabruh не входит по ключу — root НЕ закрыт, разбирайся
```

Время в строках фазы 1 и 2 берётся с часов сервера, поэтому может отличаться от локального.

## Важно

- В `ignoreip` попадает IP, с которого ты запускал скрипт. Если IP у тебя динамический, позже он сменится и белый список устареет. Сам по себе вход по ключу банов не вызывает: fail2ban реагирует на неудачные попытки входа.
- После выполнения войти под `root` по SSH уже нельзя. Повторный запуск на том же сервере упадёт на первом же подключении, и это нормально.
- На серверах с cloud-init скрипт пишет `/etc/ssh/sshd_config.d/00-hardening.conf`. Этот файл читается раньше `50-cloud-init.conf`, поэтому его настройки главнее.
